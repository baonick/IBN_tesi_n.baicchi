================================================================================
           CATALOG AND DESCRIPTION OF ERROR TYPES (IBN - DIPS)
================================================================================
Project: Translation of Network Intents into Prolog Facts for the DIPS framework
Reference script: script/catalogo_errori.py
Last update of severity criteria: October 2026

--------------------------------------------------------------------------------
1. INTRODUCTION AND GENERAL LOGIC
--------------------------------------------------------------------------------
The catalog classifies every discrepancy found between the prediction of the
language model (LLM) and the Gold Standard (ideal intent) into 4 macro-categories
(A, B, C, D), divided into specific subtypes.

Each error is associated with a SEVERITY level:
- HIGH:  Errors that modify or compromise the network intent (violation of the
         minimum requirements, hallucinations, omissions or parsing failures).
- LOW:   Benign errors in which the constraint generated by the LLM is MORE
         RESTRICTIVE than the Gold Standard, while still guaranteeing full
         satisfaction of the original intent.

================================================================================
2. MACRO-CATEGORIES AND ERROR SUBTYPES
================================================================================

--------------------------------------------------------------------------------
CATEGORY A: SYNTAX (A. SYNTAX)
--------------------------------------------------------------------------------
Formal and structural errors in the Prolog text generated by the LLM. They are
detected through direct syntactic analysis of the raw text, before the logical
comparison.
All Category A errors have HIGH severity, since they prevent the correct
compilation and execution of the logic rules in the DIPS framework.

  * Subtype: A.SYNTAX
    - Severity: High
    - Triggering causes:
      1. Missing final period:
         Every Prolog clause or fact must end with a period '.'.
         If it is missing, the line is not a valid clause.
         Example: `vnf(firewall, edge, 1)` instead of `vnf(firewall, edge, 1).`

      2. Unbalanced round brackets:
         The number of opening brackets '(' differs from the closing ones ')'.
         Example: `intent(i1, opA, 10, t1..`

      3. Unbalanced square brackets:
         Missing closing or opening square brackets '[' and ']', used to
         define lists (e.g. the VNF sequence in target/2).
         Example: `target(t1, [vnf1, vnf2).`

      4. Arity Mismatch (wrong number of arguments in the predicate):
         - intent/4: exactly 4 parameters expected (IntentID, ProviderOp, NumUsers, TargetID).
         - target/2: exactly 2 parameters expected (TargetID, [VNFList]).
         - vnf/3: exactly 3 parameters expected (VnfID, Edge/Cloud, HW).
         - vnfXUser/4: exactly 4 parameters expected (VnfID, l, Range, HW).
         - propertyExpectation: accepts ONLY 6 parameters (changing properties)
           or 9 parameters (non-changing properties). Any other number of
           arguments generates an arity error.

  * Subtype: A.FILE_NOT_FOUND
    - Severity: High
    - The LLM prediction file is missing or not reachable at the expected path.


--------------------------------------------------------------------------------
CATEGORY B: WRONG VALUES (B. WRONG VALUES)
--------------------------------------------------------------------------------
Errors in the literal, scalar or quantitative values of the parameters, while
the predicate structure and the VNF entities remain unchanged.

  * Subtype: B.TYPE_MISMATCH
    - Severity: High
    - Description:
      The property type in propertyExpectation does not match the Gold.
      Example: generated `security` instead of `compression`, or `delay`
      instead of `latency`. It completely alters the nature of the requirement.

  * Subtype: B.HARD_SOFT_MISMATCH
    - Description:
      Discrepancy between a strict constraint ('hard') and a desirable/flexible
      constraint ('soft') in the 3rd parameter of non-changing properties
      (9 parameters).
    - Severity:
      - LOW:    LLM generates 'hard' while Gold requires 'soft'.
                Rationale: Enforcing as mandatory a constraint that could have
                been negotiable makes the constraint stricter, but does not
                violate the user's original request.
      - HIGH:   LLM generates 'soft' while Gold requires 'hard'.
                Rationale: Making a binding requirement optional may allow
                the network to violate a critical security or performance
                constraint.

  * Subtype: B.VALUE_UNIT_MISMATCH
    - Description:
      Discrepancy in the numeric value, the unit of measurement or the operator.
      It involves:
      - Parameters 1, 2, 3, 4 of non-changing propertyExpectation (Operator, Hard/Soft, Value, Unit).
      - Parameter 1 placeholder '_' in changing propertyExpectation (6 arguments).
      - Parameters of intent (ProviderOp or NumUsers).
    - Severity:
      - LOW (More restrictive constraint exception on Latency and Bandwidth):
        1. Latency: LLM value < Gold value (e.g. LLM=50 ms, Gold=70 ms).
           Guaranteeing a lower latency is a qualitative improvement and fully
           satisfies the maximum threshold imposed by the intent.
        2. Bandwidth: LLM value > Gold value (e.g. LLM=100 Mbps, Gold=50 Mbps).
           Guaranteeing a higher bandwidth amply satisfies the minimum request.
      - HIGH:
        In all other cases:
        - Higher latency (e.g. LLM=90 ms instead of 70 ms).
        - Lower bandwidth (e.g. LLM=30 Mbps instead of 50 Mbps).
        - Wrong unit of measurement (e.g. 's' instead of 'ms', or 'kbps' instead of 'mbps').
        - Inverted comparison operator (e.g. 'ge' instead of 'le').
        - Non-numeric or non-comparable values.


--------------------------------------------------------------------------------
CATEGORY C: WRONG VNFs AND TOPOLOGY (C. WRONG VNFs)
--------------------------------------------------------------------------------
Errors related to the identification of the network functions (VNFs), their
architectural placement (Edge/Cloud), their hardware profile or the topological
relationships in the chain.

  * Subtype: C.TOPOLOGY_ERROR
    - Severity: High
    - Description:
      - A wrong, hallucinated or non-compliant VNF in the role of Source or
        Destination within propertyExpectation.
      - Wrong VNF name or identifier in the vnf/3 or vnfXUser/4 predicate.

  * Subtype: C.SOURCE_DEST_SWAP
    - Severity: High
    - Description:
      Inversion between Source and Destination in CHANGING properties
      (6 parameters: security, compression, logging, privacy, caching,
      decoding, encoding).
      Rationale:
      In 6-parameter properties the order of traffic along the service chain
      is strictly directional (e.g. compress upstream and decompress downstream).
      Swapping Source and Dest overturns the functional logic of the intent.
    - SPECIAL NOTE (9-parameter properties):
      In 9-parameter properties (e.g. latency, bandwidth, or placement
      constraints such as affinity/same), the link between the two VNFs is
      bidirectional or symmetric. Consequently, a Source/Dest swap on
      9-parameter properties is NOT considered an error and is accepted by
      the script.

  * Subtype: C.WRONG_TARGET_CHAIN
    - Severity: High
    - Description:
      The ordered list of VNFs in the predicate target(TargetID, [VNFList])
      does not match the ideal one. It indicates an error in the traversal order
      of the Service Function Chain (SFC) or the omission/addition of a VNF in
      the chain.

  * Subtype: C.WRONG_ASSIGNMENT
    - Severity: High
    - Description:
      Wrong assignment of the VNF deployment characteristics:
      - Wrong Edge vs Cloud assignment (parameter 1 of vnf/3).
      - Wrong Hardware requirement (parameter 2 of vnf/3 or parameter 3 of vnfXUser/4),
        e.g. missing request for hardware acceleration or dedicated HW.
      - Wrong scaling parameters or user constraints in vnfXUser/4.


--------------------------------------------------------------------------------
CATEGORY D: INSERTIONS AND REMOVALS (D. INSERTIONS/REMOVALS)
--------------------------------------------------------------------------------
Logical facts for which no match (pairing) was found between the prediction
and the Gold Standard in the set-based comparison.

  * Subtype: D.INSERTION (False Positive)
    - Severity: High
    - Description:
      Prolog fact generated by the LLM that has no counterpart in the Gold intent.
      It represents a "hallucination", i.e. the introduction of constraints,
      VNFs or expectations not requested by the network customer.

  * Subtype: D.REMOVAL (False Negative)
    - Severity: High
    - Description:
      Prolog fact present in the Gold Standard but completely omitted by the LLM.
      It represents an unsatisfied intent, in which the model forgot to
      formalize a contractual requirement (e.g. a latency constraint,
      a security level or a VNF of the chain).

================================================================================
4. IMPACT OF FILES WITH ONLY "LOW" ERRORS
================================================================================
The catalogo_errori.py script contains a dedicated section in the individual
reports: "FILES WITH ONLY LOW ERRORS".

These files represent predictions in which the model did NOT make any serious
syntactic or logical error: all business and network requirements are satisfied,
and the only deviations are improvements (e.g. lower latency requested, higher
bandwidth, or application of hard constraints instead of soft ones). Such outputs
can be considered operationally valid or fixable with minimal post-processing
rules.
